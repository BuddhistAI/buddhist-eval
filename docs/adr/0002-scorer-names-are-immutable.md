# Scorer names are immutable

The BuddhistAI arena imports one version of buddhist-eval at a time, so it cannot run the exact package version each Challenge was created with. Instead, a Scorer's name is a contract: once released, `cer` always computes the same thing, and any change to its output ships under a new name such as `cer_v2`, with the old Scorer left registered. Challenges store the package version they were created with for audit only. We rejected running a separate environment per package version, because the naming rule already keeps scores comparable without a process per version. The cost is that a release that changes an existing Scorer's numbers is a breaking change and must be caught in review; the registry tests pin each Scorer to the batch function it wraps for that reason.
